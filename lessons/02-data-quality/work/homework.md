## H1 Правила функции

Функция `clean_export()` принимает исходную таблицу и возвращает три результата: очищенные записи (`clean`), записи с ошибками (`quarantine`) и журнал очистки (`audit`).

Функция удаляет повторные записи, проверяет уникальность ключа `source_row`, убирает пробелы в коде округа и преобразует числовые столбцы в числа. Проверяется наличие ключа, положительная сумма кредита, код исхода от 1 до 3 и код округа `11001`. Некорректные записи отправляются в карантин с указанием причины.

## H2 Доход и баланс

- Количество очищенных записей: `len(clean)`.
- Количество записей с известным доходом: `clean['income'].notna().sum()`.
- Количество записей с неизвестным доходом: `clean['income'].isna().sum()`.
- Средний известный доход: `clean['income'].mean()`, в тысячах долларов в год.

При расчёте среднего дохода пропущенные значения не учитываются. Баланс записей проверяется по формуле: `input == replays + clean + quarantine`.

Исходная таблица сохраняется без изменений, поскольку функция работает с её копией. Это проверяется с помощью `assert_frame_equal(export, raw_copy)`.

## H3 Проверка года и виды проблем

Для проверки года была создана копия таблицы, в которой год первой записи заменён на 2022. Проверка соответствия 2023 году возвращает `False`, что подтверждает обнаружение нарушения.

- Исходный пропуск: отсутствующее значение дохода. Запись сохраняется, если остальные поля корректны.
- Новая ошибка преобразования: например, текст `abc` вместо числа. Значение заменяется на `NaN`, а ошибка учитывается в журнале `parse_errors`. Если это доход, запись может остаться в очищенной таблице; если это обязательное числовое поле, запись отправляется в карантин.
- Необычная сумма: например, сумма кредита `-100` или `0`. Такая запись отправляется в карантин с причиной `invalid_loan_amount`. Большая положительная сумма сама по себе не считается ошибкой по заданным правилам.
